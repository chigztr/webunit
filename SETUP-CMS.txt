4. CMS AUTHENTICATION
---------------------

Decap CMS uses the GitHub backend.

Authentication is handled by this Cloudflare Worker:

https://webunit-cms-auth.cvyas.workers.dev

Expected Worker endpoints:

/auth
/callback

Cloudflare Worker runtime variables/secrets:

GITHUB_CLIENT_ID
GitHub OAuth Client ID

GITHUB_CLIENT_SECRET
GitHub OAuth Client Secret
This must be stored as a Cloudflare Secret.

Never commit the GitHub Client Secret to GitHub.

10. EMAIL / IONOS
-----------------

The domain is registered with IONOS and email remains with IONOS.

Cloudflare DNS must retain the IONOS mail records.

Important records include:
- MX records
- SPF TXT
- DMARC CNAME
- autodiscover CNAME
- s1-ionos._domainkey
- s2-ionos._domainkey
- s42582890._domainkey

Do not delete these when changing website DNS records.


11. PUBLISHING A CHANGE
-----------------------

Normal workflow:

1. Visit https://webunit.co.uk/admin/
2. Login with GitHub.
3. Make the required edit.
4. Click Publish.
5. Confirm the change appears as a new GitHub commit.
6. Cloudflare Pages deploys automatically.
7. Refresh https://webunit.co.uk

If the Pages URL updates but the custom domain initially looks old, test a private
browser window or another network before changing DNS. Browser/DNS caching may be
the cause.


12. TROUBLESHOOTING
-------------------

CMS login fails:
- Check the Cloudflare Worker is deployed.
- Check GITHUB_CLIENT_ID exists.
- Check GITHUB_CLIENT_SECRET exists as a Secret.
- Check the GitHub OAuth callback is correct.
- Check admin/config.yml points to the Worker.

CMS publishes but website does not update:
- Check GitHub for a new commit.
- Check Cloudflare Pages Deployments.
- Test the pages.dev URL.
- Hard refresh/private-browser test.

Email fails after DNS changes:
- Verify MX, SPF, DKIM, DMARC and autodiscover records in Cloudflare DNS.


13. NETLIFY

tested successfully.

The old Netlify project may be retained temporarily as a backup and later removed.
